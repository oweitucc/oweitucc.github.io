Community health data pipeline

A reference design for turning field health data into one trustworthy record per person.

Health programmes collect data in several tools, on paper and across teams. This design brings those sources together, matches people across them, and gives programme staff a reporting layer they can query. It is built local and on-premises first, so a team can run it on its own hardware with no cloud dependency. The same design has been adapted for cloud-native and hybrid deployments.

How data flows

One person, one record

The same person can appear in several tools with spelling differences or missing fields. Matching runs in four steps, and only the third involves a person:

  1. Exact match on stable identifiers links the record straight away.
  2. High-confidence fuzzy match uses trigram similarity on names and other fields, and links only above a strict threshold.
  3. Human review queues the uncertain cases for staff to confirm or reject.
  4. New record is created only when nothing plausible matches.

Nothing is merged silently when confidence is low, so reports can be traced back to the source records.

Running it locally, in a hybrid setup, or in the cloud

The services are packaged with Docker Compose, using a base file and per-environment overrides. That is what lets the same design move between environments without being rewritten.

VariantWhere it runsWhen it fits
Local or on-premisesEvery service on hardware the team controls, reached over a private VPN.Limited or costly connectivity, strict control over where health data lives, minimal running costs.
HybridSensitive or core components stay local; selected components move to cloud infrastructure, linked over the private network.Teams that need local control of data but want cloud reach or capacity for some functions.
Cloud-nativeServices run on a cloud platform in place of local hardware.Organisations already standardised on a cloud provider, or needing to scale across many countries.

Delivery

  • Private access over a WireGuard-based VPN; Caddy handles TLS.
  • Deployment through GitHub Actions.
  • Reporting in Metabase for programme and data staff.
